# Reapers

An augmented reality game where you are a reaper and dead NFTs are what you hunt.

## Why it exists

Most NFT collections are dead: thousands of pictures nobody wants, sitting in wallets at a floor price near zero. Reapers gives them one last use. You buy one, release it into the spirit realm, hunt it down through your phone's camera, and absorb it to grow stronger. Absorbing destroys it, so every hunt takes a dead NFT out of circulation for good.

## What makes it different

You are bound to a reaper you did not choose, and the phone is its sight. The hunt is not won by tapping fast. It is won by keeping still: creep up on a husk without startling it, hold the phone steady while it shrieks at you, and catch it in a soul orb timed by holding on while a ring closes. The biggest husks are a whole collection piled into one body at a real place, and take a circle of four who all have to hold still at the same moment.

## What is in the game

- The shuffle: six classes, each with its own silhouette, weapon and perk, and a few hundred looks apiece.
- Eighteen permanent birth gifts and four temperaments. Each reaper's remembered successful hunts awaken its own power at levels five, twelve and twenty.
- The hunt: trace a sigil to draw the husk out (harder for rarer husks), then stalk, fire, shriek, capture.
- Husks that are creatures with a place in the room: walkers on the floor, fliers in the air, leaping onto counters and hiding behind them.
- Arts, learned by absorbing the creatures that carry them: Cinder (fire, lobbed over cover), Rime (ice that freezes) and Gale (wind that blows a husk out of hiding).
- Two heavy weapons for any class: a greatsword that stops a husk in its tracks and an axe that bites the body anywhere.
- A roll of luck on every absorption, decided and signed by the server.
- A vault and a market, an armory of weapons and outfits, a codex, levels and collection sets.
- Rifts: four-reaper raids, with shades filling the seats nobody takes.
- A server that keeps players' books and replays every hunt before paying for it. The game also runs entirely offline.
- An on-chain program that escrows a released husk and burns it when the server's signed receipt says it was absorbed.

The five collections are real ones from Solana's first wave (Degenerate Ape Academy, Thugbirdz, Pesky Penguins, Sollamas, Solarians), each with a creature we modelled ourselves; those stand-ins are not licensed. Buying a husk is still simulated. On devnet and on a localnet the game escrows and burns real demo husks with the player's wallet; the simnet rehearses the same on the device. [docs/nfts.md](docs/nfts.md) lists every stand-in and where the real thing plugs in. [docs/gameplay.md](docs/gameplay.md) is the rulebook, and ends with what is not built yet.

### Where it stands

Everything is Rust: the rules, the server, the program, the tools and every screen of the game. The reapers, the husks, the studio, the hunt and the rifts are drawn in 3D on the GPU by `leptoskit_3d`, and the hunt follows the phone through `leptoskit_xr`: ARKit, ARCore or the rotation sensor, and a dragged finger on a desktop. Each of these views sits behind one of the app's seams. [crates/reapers_app/README.md](crates/reapers_app/README.md) has the seams and what each platform still lacks.

## The stack

| Crate | What it is |
| --- | --- |
| [`reapers_rules`](crates/reapers_rules) | Every rule, catalogue and number. Plain Rust, built natively for the server and as Wasm for the game. |
| [`reapers_receipt`](crates/reapers_receipt) | The absorption receipt the server signs and the program checks. |
| [`reapers_program`](crates/reapers_program) | The on-chain program, on [pina](https://github.com/pina-rs/pina): husk escrow, and burns that carry the receipt. |
| [`reapers_program_client`](crates/reapers_program_client) | The program's instructions and accounts, generated by pina, for the server, the tools and the game. |
| [`reapers_api`](crates/reapers_api) | Every request and answer between the game and the server, declared once as a leptoskit operation. |
| [`reapers_db`](crates/reapers_db) | The server's tables and their migrations. |
| [`reapers_server`](crates/reapers_server) | The keeper: the server, on leptoskit's server crates and PostgreSQL. |
| [`reapers_app`](crates/reapers_app) | The game, on [leptoskit](https://github.com/leptoskit/leptoskit): one tree of screens for the browser and the iOS and Android apps. |
| [`reapers_landing`](crates/reapers_landing) | The landing page: what the game is and a way into it, a static site on leptoskit. |
| [`reapers_ops`](crates/reapers_ops) | Deploys, configures and rehearses the program; brings up a localnet. |
| [`xtask`](crates/xtask) | The repository's own tools: the checks, the guard on `main`, the merge, the art and music builds, and the depth model's fetch. |

Rust is pinned by `rust-toolchain.toml` (a nightly, the one leptoskit pins); rustup installs it, with its Wasm and mobile targets, the first time `cargo` runs here. leptoskit and Solana Kit come from git, each at one revision, pinned in the root `Cargo.toml`. The models, music, portraits, typefaces and mark the game ships are in [`assets/`](assets).

## Run it

You need the leptoskit CLI, at the revision the workspace pins:

```sh
cargo install --locked --git https://github.com/leptoskit/leptoskit \
  --rev 6264b69e813c468c118478aef3b51968e6a89cd6 leptoskit_cli
```

### In the browser

```sh
cd crates/reapers_app
leptoskit dev --platform web          # http://127.0.0.1:3010, rebuilt as you edit
leptoskit build --platform web        # dist/, for any static host
```

That is the whole game with no server: the player's books are kept in the browser.

### The landing page

The landing page is a second leptoskit frontend beside the game, web only. [`leptoskit.workspace.toml`](leptoskit.workspace.toml) names the two; `leptoskit workspace check` checks it.

```sh
cd crates/reapers_landing
leptoskit dev                         # http://127.0.0.1:3011, beside the game's 3010
leptoskit build --release             # dist/, a static site, with brotli and gzip copies
```

Its ways into the game go to `http://127.0.0.1:3010/`, the game's `leptoskit dev`, unless the build names where the game is deployed: `REAPERS_APP_URL=https://play.example/ leptoskit build --release`. A release build optimizes the Wasm with `wasm-opt`, from [Binaryen](https://github.com/WebAssembly/binaryen), which must be on `PATH`.

### On iOS and Android

```sh
cd crates/reapers_app
leptoskit dev --platform ios          # in every booted iOS Simulator, starting one if none is (needs Xcode)
leptoskit dev --platform android      # on every attached Android phone or emulator (needs the Android SDK, NDK and CMake)
leptoskit build --release --platform ios       # the iOS app, for a device
leptoskit build --release --platform android   # the Android app
```

`leptoskit dev` with no `--platform` runs every platform this machine can, and swaps each rebuilt guest into the running apps without reinstalling them. The app is the same screens as the browser's, run as a Wasm guest inside a native host. The camera hunt targets the two phones; the browser plays everything else.

### Build flags

Flags are environment variables of `leptoskit dev` and `leptoskit build`, read when the app is compiled:

| Variable | Effect |
| --- | --- |
| `REAPERS_SERVER_URL=http://localhost:8080/` | Play against the server. Without it the game is fully offline. |
| `REAPERS_CLUSTER=devnet` | With a server, real demo husks on devnet, moved by the player's wallet. `localnet` is a validator on this machine. |
| `REAPERS_SOLANA_RPC_URL=https://…` | With a cluster, the RPC the game reads and sends through. Defaults to devnet's public RPC, or `http://127.0.0.1:8899` for `localnet`. |
| `REAPERS_SIMNET=true` | The offline game on a pretend devnet: a burner wallet, and a signed Solana transaction for every airdrop, purchase, escrow and burn. |
| `REAPERS_SURFPOOL_URL=http://localhost:8899` | With the simnet, a real local Solana RPC in the explorer: health, balance and a faucet. |
| `REAPERS_DEMO_RIFT=true` | With a server, waives collection attunement so several real clients on one development server share a demo rift. Ignored by release builds. |
| `REAPERS_AUTOPLAY=true` | A simulated player fights every hunt and rift. |
| `REAPERS_GALLERY=true` | Debug builds open at the reaper bench. |

A combination that cannot work (the simnet with a server, a demo rift without one, Surfpool without the simnet, a cluster without a server) opens a notice saying why, instead of a game that half works. The native apps only reach the origins listed under `[native.plugin-options.http]` in `crates/reapers_app/leptoskit.toml`: add a deployed server's or RPC's origin there. The keeper's live rift socket also needs the corresponding `ws://` or `wss://` origin under `[native.plugin-options.websocket]`; this plugin starts with the host even in an offline build.

### On the simnet: a devnet rehearsal

To show the game's chain story without any cluster, for a demo or a hacker house:

```sh
cd crates/reapers_app
REAPERS_SIMNET=true leptoskit dev --platform web
```

Binding a reaper makes a burner wallet and airdrops its SOL. Buying a husk, releasing it into escrow and absorbing it each post a signed transaction built with the program's own instructions, and the burn carries the keeper's Ed25519 receipt, checked the way the program checks it. A slip confirms each transaction as it lands, and **Simnet ledger** in the sanctum is the explorer. Nothing leaves the device. With Surfpool running (`surfpool start --offline --no-deploy`), add `REAPERS_SURFPOOL_URL=http://localhost:8899` and the explorer shows the validator's health and the burner's real balance there, with a faucet. See [docs/solana.md](docs/solana.md#the-simnet).

### With the server

The server needs PostgreSQL and a passwords file:

```sh
cp crates/reapers_server/config/passwords.example.toml crates/reapers_server/config/passwords.toml   # once
cargo run -p reapers_server           # http://127.0.0.1:8080, migrations applied on start
```

[crates/reapers_server/readme.md](crates/reapers_server/readme.md) says how to keep a PostgreSQL for it under the repository, and lists its settings. Then point a build at it, and give the server the web game's origin:

```sh
REAPERS_ORIGIN=http://127.0.0.1:3010 cargo run -p reapers_server
cd crates/reapers_app
REAPERS_SERVER_URL=http://127.0.0.1:8080/ leptoskit dev --platform web
```

An Android emulator reaches this machine at `http://10.0.2.2:8080/`; a phone needs your computer's LAN address, added to the app's HTTP origins.

### On a localnet, and on devnet

A cluster build plays against the server and moves real husks with the player's wallet: the server keeps the books and signs receipts, the wallet holds the husks and signs every transaction that moves one.

```sh
cargo run -p reapers_ops -- localnet  # Surfpool with the program, initialized, and the demo husks minted
# then the server on it, as docs/deploy.md ("The game on a localnet") says, and:
cd crates/reapers_app
REAPERS_SERVER_URL=http://127.0.0.1:8080/ REAPERS_CLUSTER=localnet leptoskit dev --platform web
```

On devnet, build against a server configured for it:

```sh
REAPERS_SERVER_URL=https://keeper.example/ REAPERS_CLUSTER=devnet leptoskit build --platform web
```

[docs/deploy.md](docs/deploy.md) is the runbook for deploying the program to devnet and playing on it; [docs/program.md](docs/program.md) says what the program does and why it is safe.

### Several players, one demo enemy

To show several real people attacking the same rift without first hunting a collection, build every client against the same development server with the demo flag:

```sh
REAPERS_SERVER_URL=http://127.0.0.1:8080/ REAPERS_DEMO_RIFT=true leptoskit dev --platform web
```

Take the oath, open **Rifts**, and choose the same site on every client. Open the rift on every client before anyone presses **Stand ready**, so they are all present when the count begins. The server seats them in one circle around one shared enemy: the roster, the ward and every shriek are synchronised, empty seats become shades, and each player is paid separately, once, by the server's own books. The demo waives only the collection attunement, is refused by staging and production servers, and is kept in circles separate from ordinary play.

## Work on it

```sh
cargo xtask hooks install     # once per clone: guard main (see below)
cargo xtask check             # format, clippy, every build and every test
cargo xtask check --fast      # the same without the server's PostgreSQL tests
cargo xtask build-art         # rebuild every model and portrait (Blender 5.1, gltfpack 0.25)
cargo xtask build-music       # fetch and re-encode the music (curl, ffmpeg)
cargo xtask build-sfx         # build the recorded combat effects (Python, ffmpeg, bsdtar)
cargo xtask fetch-depth-model # fetch the phones' depth model, 27 MB, not committed (curl)
```

`cargo xtask check` needs `pina` 0.24.0 and Agave's `cargo-build-sbf` for the program's build, and PostgreSQL's binaries for the server's tests; it says which is missing, and how to get it, before it starts. Every push to `main` and every pull request runs it on GitHub Actions; [.github/workflows/ci.yml](.github/workflows/ci.yml) installs the same tools.

Every change lands as a pull request, and the checks that let it land run on the machine that lands it:

```sh
git switch -c feat/your-change
cargo xtask merge             # push, open the pull request, check, land
```

`cargo xtask merge` pushes the branch, opens a pull request into `main` (or reuses the open one), runs every check, and fast-forwards and pushes `main`. GitHub marks the pull request merged as soon as its head commit is on `main`, so pushing `main` is the merge; the command then comments the check report on the pull request, confirms GitHub marked it merged and deletes the branch on origin. It needs the GitHub CLI, signed in with `gh auth login`.

The hooks make this the only way in: `main` refuses any commit that `cargo xtask merge` has not just checked. Nothing waits on GitHub Actions, which runs the same `cargo xtask check` as a mirror.
